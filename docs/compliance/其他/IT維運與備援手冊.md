## 1. 接管清單與日常責任

核對Person-git/person-convert-backend、本機PDF-Convert、Cloudflare convert-bench與Render person-convert-api；不可操作內控／CRM資源。指定維護者、代理人、資訊／資料主責、供應商及事故通報窗口。由公司程序申請／撤銷外部帳號與最小權限、MFA及復原方式，不在文件中保存Token／密碼。

日常監控由公司核定：站台／API可用性、排隊／失敗／逾時、異常請求量、帳號異動、依賴更新與費用；health僅存活，不能確認部署commit或轉檔品質。不得為監控長期上傳真實機密文件。

## 2. 版本發布

1. 核對工作區、Git遠端、待發布commit及差異；確認必要測試／允收與部署授權。
2. 本機測試使用tests/fixtures公開資料；CI／單元測試不代表公司實機驗收。擷取工具版本、結果及產物雜湊並存受限證據庫。
3. 前端直接上傳完整frontend目前27檔與icons，禁止帶入docs、tests、私有文件、.venv／暫存。前端變動同步更新PWA cache與版本參數，保留離線排除規則。
4. Pages上核對帳戶及convert-bench的Production，再上傳；不要因Git推送成功就認為前端已部署。核對公開檔案雜湊、下載、主要流程與新版提示。
5. Render依既有設定從main自動部署，正式設定仍需核對；Docker僅COPY後端兩支程式。查最後成功commit及health，再用核准合成資料測試；相同API版本0.3.0不等於相同commit。
6. 保存批准、發布識別、雜湊、日誌與回復版本。僅改文件通常無需再上傳前端；Git推送仍可能觸發Render自動部署，須事前評估影響。

## 3. 本機與伺服器處理

後端PORT由環境注入，預設8000；Docker需Ghostscript。Python直接依賴見requirements.txt，完整OS／間接依賴須以實際建置清冊補足。本機.venv為執行環境，不能當發布包；不要為測試逕自安裝Docker／WSL或改裝置政策。

公司核准的本機測試可使用`node tests/test_*.cjs`逐檔及Python pytest；測試報告須記實際命令與結果。`scripts/verify_service.py`需指定base-url及output，會上傳合成檔；`benchmark_live_synthetic.py`預設指向正式Render，未核准不可直接執行。公開六頁PDF已固定在tests/fixtures，不能刪除它當作暫存。

## 5. 日常維運與故障排除

本章為操作程序，並非已啟用的自動監控服務，也不是本次實測紀錄。以下週期為建議，負責人、值勤／非上班時間、告警管道及處理時限由公司核定。只操作PDF-Convert資源；無需為查故障安裝Docker／WSL、停用防護或上傳機密原檔。

### 5.2 先判斷影響範圍

1. 先保住已完成結果與標註：能下載便先下載；記錄模式與錯誤，不立即重整或清快取。若正在工作，先取消並等待停止，再決定重試。
2. 確認實際工具、處理模式、開始時間、頁數／大小及是否只有某個檔案失敗。Word自動／OCR及Excel／向量通常是本機；Word後端排版及後端壓縮才涉及Render。
3. 用同一瀏覽器的公開小樣本判斷「特定文件」或「所有文件」問題；不要以陌生線上轉檔網站測機密原檔。只在核准裝置／網路交叉比較，不繞過公司網路或安全控制。
4. 依下表定位，再進入5.3；修復後依5.5複測，而非只看畫面錯誤消失。

| 觀察 | 優先檢查 | 判斷限制 |
| --- | --- | --- |
| 網站開不起來，多台核准裝置相同 | 網路／DNS／Pages可用性、發布與供應商事件 | 先區分公司網路，不能憑一次失敗判定Cloudflare故障 |
| 網站可開，但OCR／Excel／保護／向量引擎無法載入 | CDN連線、套件下載／快取、瀏覽器限制 | 能開首頁不代表所有CDN可達；清快取反而會重新下載 |
| 本機模式正常，僅後端模式失敗 | API網址、Render服務／排隊／用量與錯誤 | health正常仍可能轉換失敗；不更換到未知API網址 |
| 只有某一PDF或特定頁失敗 | 損壞／加密／無文字層／複雜度／容量 | 頁數少也可能複雜；先縮小指定頁範圍 |
| 只有單一瀏覽器／裝置失敗 | 記憶體、版本、站台儲存、擴充功能或裝置政策 | 依公司允許程序測試；不逕自停用防護或擴大權限 |
| 更新後顯示舊介面或不同功能不一致 | 前端是否確實部署、PWA／快取混版 | 先下載結果並保存未輸出標註，再手動重新載入 |

### 5.3 常見症狀處理表

| 編號／症狀 | 優先原因與安全處理順序 | IT需查看／升級條件 |
| --- | --- | --- |
| OP-01 白頁／引擎警示 | 查核准URL→確認網路→查看非敏感瀏覽器錯誤→比對公開前端與CDN載入；已發布變更則核對完整frontend與icons | 多裝置均失敗或同一公開資源反覆錯誤，交維護者核對部署；不要直接回復未核准版本 |
| OP-02 OCR初次很慢／語言載入失敗 | 確認語言、網路及離線資源狀態→等候本次下載或取消→連線後以一頁公開樣本重試 | 記套件載入錯誤與階段；非OCR功能正常不代表OCR套件可達；不自行換未知語料來源 |
| OP-03 轉檔慢／記憶體不足 | 確認本機／後端→減少頁數、先試一頁→降低圖片倍率或改快速文字→關閉其他大型工作 | 公開小樣本仍反覆失敗才升級；保留階段耗時，不承諾6頁應幾秒完成，也不先提高逾時值 |
| OP-04 Word疊字／缺圖／字型／數值錯 | 區分文字層與OCR、確認語言→單頁試轉→下載到Word比對來源→必要時快速文字或來源軟體另存 | 字型／背景為近似；重要數值、單位、醫療／法規文字須人工覆核；校對紅框不是Word實際渲染結論 |
| OP-05 Excel空白／列欄不正確 | 確認有可擷取文字→用列欄預覽及指定頁→來源取得原表格；掃描頁不支援Excel OCR | 表格版面／合併儲存格不保證還原；不能把OCR Word模式當Excel OCR |
| OP-06 受保護／錯誤密碼／損壞PDF | 用已知正確開啟密碼及有權副本→重新下載／從來源軟體另存→必要時單頁圖片PDF保外觀 | 未知開啟密碼、憑證與DRM不支援；圖片PDF會失去可選文字／向量；不要要求使用者通報密碼 |
| OP-07 SVG缺字／不支援元素 | 提供合法且涵蓋文字的TTF，或來源軟體轉外框→內嵌PNG/JPG→簡化濾鏡／遮罩／外部引用 | SVG5MiB、TTF20MiB與物件／引用限制；不支援時拒絕，不以整頁截圖假稱向量；核對實際向量與字型 |
| OP-08 找不到下載／再次下載不見 | 查瀏覽器下載紀錄與儲存位置→目前分頁的再次下載→確認是否已重選／重輸出／重載或超額釋放 | 單份128MiB、正式結果合計256MiB；沒有固定保存分鐘數與歷史庫。失效只能以原檔重轉，不向Render找結果備份 |
| OP-09 後端連線錯誤／400／413／422 | 核對核准API網址及模式→確認PDF格式、已解密與25MiB上限；422無文字層則改本機Word OCR | 先讀畫面／回應原因；不要把所有400當逾時。切本機模式不代表可忽略資料授權 |
| OP-10 後端503／504／500 | 503依Retry-After／畫面等候再試，避免重複提交；504減少頁數／複雜度；500記時間與種類交IT | 程式排隊30秒、轉換120秒；查名額釋放、引擎／Ghostscript／資源及部署；不無限重試或只重啟掩蓋根因 |
| OP-11 後端第一次很慢 | 核對是否僅喚醒／連線階段，待服務回應後用公開小樣本確認 | 喚醒正常不代表所有轉換會快；持續無回應依OP-09／10，不用高頻保活代替容量規劃 |
| OP-12 舊快取／離線不可用 | 先下載所有結果與標註→連線手動載入新版→檢查所需引擎／語言→公開一頁離線試轉 | 最後才按公司程序清站台資料；會失去分頁結果／偏好／離線資源，後端離線永遠不可用；無需先解除安裝PWA |
| OP-13 壓縮不縮小／畫質變差 | 無損可能本來已最佳化→查模式與前後大小→檢查代表頁及放大細節 | 後端低dpi會失真；首頁抽查不能代替全文件校對，保留原檔，不為縮小強行覆寫 |
| OP-14 加密後仍可複製／簽章失效 | 確認有無開啟密碼與操作權限、用相容閱讀器核對→解釋閱讀器可能忽略權限 | 權限不是DRM或防截圖；重新儲存可使簽章失效，須來源簽署流程處理，不宣稱加密修復簽章 |

### 5.4 重試、重新整理與變更界線

- 先記錄與下載，再重試。保留原檔；重試可產生重複下載，不能自動覆寫使用者已校對版本。
- 只縮小頁碼／改本機輸出選項可按原授權處理；改選後端、改API目的地、提供機密樣本、調整存取／付費方案或回復正式版本，依公司與使用者授權確認範圍。
- 清站台資料、重載或關閉會失去未下載記憶體結果與標註；尚有工作先等完成或取消。沒有伺服器結果庫可回復這些內容。
- 不將「先重啟、先清快取、先延長逾時」作所有問題共同解法。記錄根因、變更與回復方式；停服務／部署／權限調整沿既有變更程序。

### 5.5 處理後確認與結案

1. 以相同公開樣本、相同模式及頁碼重做原失敗步驟，記錄實際結果；相關模式如本機與後端分別驗證，不以上傳成功代替格式／內容正確。
2. 下載並開啟產物，檢查頁數／順序／文字／圖片；SVG→PDF另查是否保留向量。Word排版以Word實際顯示核對。測試範圍與需求／案例編號對照既有UT／IT／AT，不因一個樣本通過就全部結案。
3. 若涉及發布，核對前後端識別及PWA版本；若改存取或清理流程，補正向／負向與失敗路徑，必要時隔離回復演練。
4. 保存症狀、根因或「尚未確定」、處置、變更識別、複測證據、剩餘限制、結案人與日期；仍失敗則轉維護／供應商，不重複無限嘗試。重大／高風險事件由公司指定人確認結案。
